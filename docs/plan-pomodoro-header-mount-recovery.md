## 根因与修复（2026-11-25）

用户反馈「第一个番茄显示，第二个番茄就没了」后定位到真正的缺陷：

`PomodoroHeaderTimer` 在**渲染过程中**调用 `pomodoroEngine.setSettings()`。番茄处于空闲（未运行）时，`configure` 每次都返回新的状态对象并 `emit()`，而本组件又订阅了该引擎，`emit` 触发 `setState` 重渲染，重渲染再次在渲染期写回设置——形成渲染期死循环，超过 React 的更新上限后组件被丢弃。第一个番茄处于运行态，`configure` 直接返回原状态、不广播，所以正常；第一个番茄结束转为空闲后即触发死循环，组件消失，第二个番茄自然也没有。

修复：

1. 顶栏组件把 `setSettings` / `setTasks` 从渲染期移到 `useEffect`，仅在 `data.settings` / `data.tasks` 变化时同步。
2. 引擎 `configure` 在剩余量未变时返回同一状态引用，杜绝任何「设置未变仍广播」的空转。
3. `test/pomodoro.test.js` 增加回归：设置未变时 reducer 返回同一引用、引擎不广播（空闲与运行两种状态）。

结论：代码从未被覆盖；顶栏组件在当前宿主真实槽位下可注册、可渲染。消失是渲染期状态写回导致的死循环，已修复并补上回归。
