# 主题切换实施计划

## 数据与 API

1. 在 `lib/store.js` 的 `DEFAULT_SETTINGS` 添加 `theme: "studio-vivid"`；将主题 id 加入字符串白名单、状态规范化与 `updateSettings` 校验。
2. 保持旧 `state.json` 兼容：缺失或无效主题回退 `studio-vivid`，已有番茄设置不受影响。
3. 在 `todo` 工具的 `settings` 动作和公开参数中加入 `theme`，并更新对应测试。

## 客户端

1. 在 `lib/client.js` 定义单一 `THEMES` 注册表：五个稳定 id、中文/英文名称、描述、亮暗色令牌和预览色。
2. 由根节点的 `data-todo-theme` 属性映射主题令牌；宿主侧边栏所用 `--dsh-todo-*` 变量从同一来源同步，避免出现面板与会话顶栏不同色。
3. 在主面板右上角实现唯一的「插件设置」入口与右侧统一设置面板，将番茄时长、自动开始、提示音、每日目标和「外观 → 主题」集中呈现；番茄钟视图不再重复设置控件。
4. 主题选择后调用既有 `ui.onSettings({ theme })`，乐观更新后保存失败则回退并沿用现有错误反馈；统一设置面板支持 Escape 与点击遮罩关闭。
5. 实现主题弹层的焦点管理、方向键、Enter/Space、Esc、点击外部关闭，以及窄屏全宽布局。
6. 补齐中英文文案与可访问名称；不增加第二个主题或设置入口。

## 验证与发布

1. `test/store.test.js`：默认值、合法/非法主题、旧存储回退与持久化。
2. `test/tool.test.js`：`todo settings` 可读写主题，并拒绝未知 id。
3. `test/client-i18n.test.js`：五个主题注册表、选择器结构、默认主题、双语文案、键盘语义与令牌集中规则。
4. 执行 `npm test`、`node --check lib/client.js`、`npm run screenshot`；人工检查亮暗、中文/英文、窄屏，以及真实 DSH 会话页顶栏和侧边栏颜色同步。
5. 更新中英文 README 及截图，递增 `package.json` patch 版本、提交并推送，由现有发布流程发布。

## 验收

- 新用户和未保存设置的旧用户默认得到「明亮工作室绿」。
- 用户能在一个主题入口中选择五套已评审主题；切换即时生效、重启后保持，并同步到面板、会话顶栏与侧边栏。
- DSH 亮暗模式继续自动适配，优先级颜色与文字对比不退化。
- 键盘、屏幕阅读器和窄屏均可完成选择；未知/损坏主题安全回退默认值。
